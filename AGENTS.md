# Workspace Rules & SwarmForge Integration

## SwarmForge Activation Rule
Whenever the user says **"use swarm forge"** (or similar phrasing like "swarm forge", "activar swarm forge", "use swarm-forge"):
1. **Activate SwarmForge**: Immediately acknowledge and invoke the `swarm-forge` skill.
2. **Interactive Workflow Questionnaire**: Always present the guided questionnaire to determine the required mode and workflow parameters:
   - **Mode Selection**:
     1. `two-pack` (Rapid: Coder → Cleaner)
     2. `four-pack` (Spec-Driven: Specifier → Coder → Refactorer → Architect)
     3. `six-pack` (Enterprise Quality: Specifier → Coder → Cleaner → Architect → Hardener → QA)
     4. `lieutenant` (Concierge Dispatcher: Utility, Component, QA, Review routes)
     5. `project-manager` (Multi-Project Forge Supervisor)
   - **Task Intent & Scope**: Problem description, target audience, key deliverables.
   - **Technical Stack & Constraints**: HTML/CSS/JS, Framework, Stitch MCP design system.
   - **Quality Gates**: TDD, Gherkin acceptance criteria, automated E2E QA, mutation hardening.
3. **Execution Law**:
   - Strictly apply Uncle Bob's Engineering Constitution (TDD, CRAP $\le 10$, DRY, UI/Core separation, clean commits, and durable handoffs).
